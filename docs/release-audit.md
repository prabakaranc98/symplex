# Scientific and system release audit

Audit date: 2026-09-10. Scope: the current Symplex implementation, its role prompts and execution contracts, and existing persisted demonstrations. This audit made no paid model calls, ran no new scientific simulations, changed no production scientific specification, and did not increase the workspace budget. It distinguishes software checks from domain usefulness and scientific validation.

**Release assessment:** Symplex now supports a useful, inspectable investigation workflow: versioned framing and representations, explicit hypothesis critique, evidence synthesis, bounded agent-written code execution, frozen comparison contracts, revision lineage and reviewed delivery. The available record establishes synthetic software and numerical-comparison demonstrations. It does not establish reliable real-world problem solving across the six configured domains, general algorithmic discovery, or recursive self-improvement.

## What the existing demonstrations establish

**Airport investigation.** `workspace_problem_b158bae203b64b68` reached `deliverable_e22c3c5ff5a9485f`, with a recorded conditional scenario comparison. Its own reviewer correctly identified a mismatch: the proposed airport stock/flow architecture was not the executed model. The execution used bounded dimensionless indices, with physical queues, capacity, legal environmental limits, costs, spatial flows and land-use feedback omitted. This is useful for inspecting assumed feedback and exercising the user/agent workflow. It does not estimate a feasible airport location, calibrated access improvement or environmental effect. The deliverable preserves that distinction rather than pretending the proposed simulator was built.

**Biological modeling demonstration.** `workspace_problem_e549bfb336614541` contains executed hosted-Python artifacts, including code, CSV/JSON and PNG files. The earlier `compute_package_f4e51a4a1524469a` compared linear absorption with saturable absorption under a common breakdown law. The later `complex_system_ed37e3f2bd6c49fe` and frozen `experiment_protocol_3b15077478b64e09` instead compare linear breakdown with saturable breakdown under common linear absorption. The revised computation is `compute_package_f97ef4005cc24544`; the host comparison is `experiment_comparison_1a3b4e80bae94d53`.

This is a substantial semantic branch change. The saved revision record explicitly moves saturation from absorption to breakdown; changes the nominal dose from 30 to 10 g-equivalent; changes rates rather than merely converting hours to seconds; changes the horizon, solver, sampling grid, fixture matrix and metrics. The old outputs were inspected and were not reused as observations. Consequently, the second computation is a new frozen synthetic comparison, **not evidence that a successive version improved on the first biological model**.

The later saved results report 36 integrations: nine fixtures, two structures and two tolerances. They report terminal absorption of approximately 9.938780 and 9.870006 g-equivalent, a difference of 0.068774 under the new assumptions. Reported normalized mass residuals are approximately 1.42e-15 and 1.07e-15; reported refinement differences are approximately 7.99e-11 and 7.66e-11. These are useful numerical diagnostics. The difference meets the prospective synthetic discrimination threshold, but the threshold is not an established biological effect size. There are no measured inputs, fitted biological parameters, statistical intervals or independent biological evaluator in this experiment.

The latest reviewed interpretation, `model_critique_232ef70d45034f57`, appropriately retains both structures as complementary software fixtures. `decision_brief_9cee682fc4344167` also declines to name a biological winner. Time-resolved measurements of the relevant pools, observation error, losses and variation across conditions would be needed to distinguish competing mechanisms and assess identifiability. This audit does not propose or conduct a biological intervention.

## Prioritized findings and small fixes

**1. Reviewer context can hide work that already exists.** At the start of this audit, the actual biological reviewer context allocated 7,000 characters to results JSON, 7,000 to raw CSV, 1,932 to sensitivity CSV and only 68 to the manifest. It never reached `symplex_model.py`; the working-artifact budget also omitted the existing host comparison. The decision brief therefore requested source, plots and comparison work already present in storage, and omitted runnable source from its consumable list. This is an actual user-value failure, not a hypothetical model limitation.

Small fix: supply a compact, complete file inventory with stable IDs, hashes, sizes, media types and inspection status independently of content excerpts. Reserve context for the frozen protocol, current system, host comparison, executable source and compact diagnostic summary before sampling raw data. Distinguish “available but not inspected” from “missing.” Re-run only the relevant context/delivery check if needed; another complete paid simulation is unnecessary. The deterministic audit script records current reviewer omissions, so this condition can be checked after a fix without a model call.

**Resolved during this audit:** the host now prioritizes source and structured experiment diagnostics, provides the complete current-package inventory, removes the bulky result schema from the protocol's prompt projection while uploading its full file for computation, and prioritizes the host comparison. A fresh read-only assembly for the biological case includes the source, experiment JSON, manifest, frozen protocol and host comparison, with seven files inventoried. The earlier decision brief is immutable and predates this correction; it has not been regenerated. Inventory-only references may be offered as consumable files, while scientific claims remain restricted to supplied artifact content. This fixes availability and prioritization, not independent validation or complete source inspection: the code excerpt is still capped at 7,000 characters.

**2. Scientific acceptance still trusts maker-reported booleans.** The generic host recomputes metric deltas and checks required diagnostic IDs, but accepts `Diagnostic.passed` from the program author. In the biological protocol, mandatory absolute limits such as 1e-7 are textual; normalized-error metrics also permit a relative degradation allowance of 1.0. The observed sample reports much smaller errors, so the issue is not an observed numerical failure. The failure mode is that a later program could report a false passing boolean while violating the textual bound.

Small fix: add typed diagnostic observations, bounds, units, quantifiers over runs and raw-output references to the frozen protocol. Recompute admissible checks from structured outputs in host-owned code. Preserve the distinction between algebraic/numerical checks, independent reproduction and empirical validation. Until that exists, the current `independently_validated=false` and `promotion_allowed=false` fields must remain in the UI, exports and decision logic.

**3. Model discrimination should not masquerade as an optimization win.** `terminal_a` is minimized in the biological example to detect delayed synthetic transfer. The generic comparer consequently labels the saturable fixture `promising_under_model` and places it on the Pareto frontier. That is a comparison under a declared discriminator, not evidence of a better biological model or intervention. The latest decision brief correctly qualified it, but the raw label can still invite overinterpretation.

Small fix: type a metric's purpose as diagnostic, discriminator, predictive score or decision objective, and derive result language from that purpose. Use “separation observed under the fixture” for this experiment. Require evidence appropriate to the purpose before ranking models or interventions. Preserve both candidates even when one wins an arbitrary point-estimate direction.

**4. Model, intervention and method versions must remain separate.** Current contracts distinguish `complex_system`, `candidate_design` and `method_candidate`. Compute revisions now have explicit predecessor artifacts and code/result uploads; the archive retains earlier candidates and links their evaluations. This is substantially better than rewriting a single answer. However, a structural model change plus new data, parameters and scoring rules cannot be counted as the same controlled comparison. General candidate discovery does not yet have an independently measured diversity/quality archive or a reusable-method acceptance service.

Small fix: record a change classification and comparability contract on every revision: mechanism, observation definition, parameterization, dataset, numerical implementation, scoring protocol and user objective. A materially changed estimand or protocol should create a clearly labeled new comparison branch. Method candidates currently remain uninstalled and unpromoted; maintain that boundary until a separate matched-compute, held-out task evaluator exists.

**5. Source links and semantic contracts are necessary but insufficient.** The typed representation checks reference integrity and declared unit/clock/coupling consistency. Evidence synthesis separates assertions, inferences, assumptions and judgments, detects declared dependency, and prevents metadata or uninspected binary pointers alone from establishing scientific support. These are valid host safeguards. They do not verify entailment, calibration, a proposed causal mechanism, or whether a declared canonical dimension is scientifically meaningful. Discovery remains bounded web/literature retrieval and a small admitted connector surface; documented resources are not acquired datasets.

Small fix: bind each observation to its measured quantity, instrument or extraction process, support in time/space, missingness and uncertainty. Preserve original modalities and extraction artifacts. Add targeted evidence/measurement checks for a chosen domain rather than a universal confidence score. The next useful action in an evidence-poor case may be a better measurement or a simpler representation rather than more generation.

**6. Prompt and harness status must match execution.** The metareasoner exposes search dimension, disconfirmation, supporting artifacts and advisory resource estimates. The host owns budgets and permissions, now validates supporting citations even on delivery, masks exhausted tools, and permits one bounded replan after a tool-limit rejection. Resource deltas report usage/reservations during tool execution; planner calls remain separate model-call records. The role roster describes distinct task/context boundaries, not a fleet of independently executing worker processes.

Small fix: remove older prompt text saying `target_id` should otherwise be empty where later paragraphs permit system, candidate and compute-package IDs. Keep one authoritative per-tool input contract. Extend failure manifests to distinguish acquisition failure, schema rejection, numerical failure, invalid comparison, unsupported inference and user clarification. Preserve all model-call and tool cost records when comparing deeper investigations.

## Use-case coverage and usefulness

The six launch briefs are configurable problem contexts, not passed domain benchmarks. `scripts/evaluate_use_cases.py` checks their exact required fields, registered tool interfaces, existing artifacts and saved file hashes. It also maps mentioned libraries to a recorded capability probe and to extension specifications. An explicit `--link` associates a related existing demonstration without treating a topical match as completion of the configured brief.

The audit run produced `/private/tmp/symplex-usecase-audit.json`: six configured briefs, two explicitly linked synthetic demonstrations, zero model calls and zero new simulations. None of the six obtains a scientific-success score from configuration coverage.

- **Prediction markets:** prepared P1 semantic admission and host scoring are a narrow reusable capability; this workspace has no demonstrated real point-in-time archive comparison for the configured brief. Useful next evidence is an admitted event-definition/forecast/outcome pack with dependency-aware evaluation.
- **Urban infrastructure:** the airport workflow demonstrates conditional feedback exploration and conservative review. Its next useful milestone is a mechanism-appropriate model matched to actual access/capacity/environment observations, not a location recommendation from normalized indices.
- **Climate, agriculture and ecology:** the brief and primary resource links exist; Hudson monitoring, climate/crop inputs and specialist models have not been admitted and evaluated for this case. A scoped quantity/time/space-aligned evidence package is the first meaningful milestone.
- **Social simulation and 3D:** the brief, visualization contracts and presentation surface can support inspection. Behavioral calibration and a validated city simulation are not established; 3D presentation must not be scored as model realism.
- **Cellular/enzymatic biology:** actual synthetic numerical artifacts and a frozen comparison exist, with the semantic branch change described above. They establish software usefulness for investigation/reproducibility work, not biological mechanism selection or health outcomes.
- **Geopolitical/economic exposure:** the brief and source-access requirements exist. No defined target, point-in-time event corpus, validated forecast or calibrated uncertainty result has been demonstrated for this case.

The saved `capabilities.json` probe detected numerical, symbolic, graph, plotting, Bayesian, geospatial and CPU-learning packages by discoverability/installed metadata. It did not run workloads or prove runtime equivalence. OpenMM, Mesa and QuantLib were absent in that probe. Generic code execution can still construct simpler models, but that fact must not imply the specialist packages or scientific adapters ran.

```sh
  --link airport_access_planning=workspace_problem_b158bae203b64b68 \
  --link enzyme_deficiency_research=workspace_problem_e549bfb336614541 \
  --output /private/tmp/symplex-usecase-audit.json
```

The output explicitly separates configured interfaces, related recorded demonstrations, checksum/provenance verification and unestablished scientific properties. It does not execute stored generated Python. The remaining release work is therefore concrete: verify the corrected delivery context, make numerical acceptance machine-checkable, preserve semantic comparison boundaries, and obtain independent evidence for a chosen real use case. Increasing model effort alone cannot replace those steps.
